# BRD-0002: Demo readiness — offline, accessibility, read aloud and a model-based tutor

Extends [BRD-0001](0001-biolab-mvp.md) for the WIT Teens hackathon jury demo. The simulation ([PRD-0001](../prd/0001-simulation-science.md)) and the approved workspace ([PRD-0002](../prd/0002-experiment-workspace.md)) are unchanged.

## Problem

BioLab will be shown in a short live jury demo. Four gaps make that demo fragile or weaker than the product it describes.

1. **It depends on the network.** Venue Wi-Fi is unreliable, and a reload without a connection shows a browser error page instead of the lab.
2. **It serves only one kind of reader.** Students with low vision need larger text and line spacing. Students who struggle with long text, or who follow better by ear, cannot have the explanation read aloud. Students who are sensitive to motion can only reduce it through an operating-system setting they may not control on a school computer.
3. **The tutor is a placeholder.** The "AI Lab Tutor" is a preview that answers nothing. Judges see a feature that does not work.
4. **It cannot answer "why?" about a student's own run.** The explanation panel describes the run, but a student cannot ask a follow-up such as "Why did biomass drop?" and get an answer grounded in that run.

## Goal

Extend the existing single-page lab, with no backend, API keys, language models, paid services or runtime network requests, so that:

1. **Offline:** after one online visit, BioLab loads and works completely with the network disabled. This covers reload, running an experiment, the three languages, Learn, About and the theme. A new version can replace the cached one without breaking a run.
2. **Accessibility settings:** a student can enlarge text (about 100 / 125 / 150 / 200%), increase line spacing, and switch reduced motion on independently of the operating system. The choices persist on that device, and the layout wraps instead of clipping.
3. **Read aloud:** a student can have the explanation, the Learn sections and the Key results summary read aloud in the current language. Only voices installed on the device are used, so it works offline. If a language has no local voice, BioLab says so and never reads the text with a voice for another language.
4. **Model-based Lab Tutor:** the preview tutor becomes a working tutor.
   - It answers a fixed set of questions, plus questions suggested by the current run.
   - Answers are generated by rules from the run, the model parameters and the healthy baseline, in all three languages.
   - It is labelled honestly: the answers are generated from the student's run and the model, not by a language model.

## Changes to BRD-0001

This BRD supersedes exactly these parts of BRD-0001. Everything else in BRD-0001 remains in force.

| BRD-0001 text | Change |
|---|---|
| Non-goal: "AI tutor and voice assistant." | **Partly superseded.** A model-based Lab Tutor (rules over the run, not AI) enters scope. The voice assistant stays out of scope (see Non-goals). |
| Non-goal: "Advanced accessibility features (voice interaction, text-to-speech, advanced visual controls)." | **Partly superseded.** Text-to-speech and the visual controls (text size, line spacing, reduced-motion override) enter scope. Voice interaction stays out of scope. |

## Non-goals

- **Voice commands (speech recognition).** Excluded by decision on 2026-09-30. Browser speech recognition, for example in Chrome, sends audio to a cloud service, which breaks the no-network and no-third-party-service constraints.
- Language models, AI-generated answers, backends, API keys, accounts, analytics and any runtime network request.
- Providing or downloading speech voices. BioLab uses only voices already installed on the device; it cannot add a Kazakh voice where the device has none.
- Offline use before the first online visit (a service worker can only cache after one load).
- Changes to the simulation, its parameters, thresholds or scientific wording rules (PRD-0001).
- A redesign of the approved workspace (DESIGN_SYSTEM §28–§30).
- App-store distribution or a custom "install app" prompt.
- A full mobile experience (DESIGN_SYSTEM §22).

## Success metric

In the live jury demo, on the demo laptop, after one online visit and with the network then disabled:

1. **Offline:** the page reloads, and a full 24-hour run completes, with Learn, About, EN/ҚАЗ/RU and both themes working. Browser developer tools show no runtime network requests.
2. **Text size:** switching to 200% text keeps the workspace usable at 1280 × 720: text wraps and nothing essential is clipped.
3. **Read aloud:** the explanation of the run is read aloud in English or Russian with a local voice. In Kazakh, it is read with a local Kazakh voice if the device has one; otherwise BioLab shows a clear message instead.
4. **Tutor:** after a stress run, asking the tutor "Why did biomass drop?" returns an answer that names that run's actual cause and values, labelled as generated from the run and the model.

Supporting evidence, recorded in the ExecPlans:
- A Lighthouse accessibility audit of the production build, with the score reported.
- `src/simulation/` SHA-256 checksums unchanged.
- lint, typecheck, tests and build pass.

## Assumptions and open questions

**Assumptions**
- The demo uses a current desktop Chrome or Edge. Other evergreen browsers work but are not the demo target.
- The demo laptop is online at least once before the demo, on the deployed site or on `npm run preview`.
- Local voices differ by device. English and Russian local voices are common on macOS and Windows. A Kazakh local voice is often absent, so the Kazakh path will probably show the "no voice" message. This can only be confirmed on the demo device itself.

**Decisions** (answered by the user on 2026-09-30)
- **Scope and time box:** S1 offline, S2 display settings, S3 read aloud and S4 the model-based tutor. Voice commands (S5) are dropped. Read aloud uses local voices only and is verified offline.
- **High-contrast theme:** deferred until after the demo (PRD-0005 out of scope).
- **Update flow:** a localized "New version available — Reload" notice. Never reload automatically (PRD-0004 §4).
- **Tutor input:** fixed and contextual chips only. No free-text field (PRD-0006 §1).
- **Offline indicator:** a small status in the header, next to the language switcher (PRD-0004 §5).
